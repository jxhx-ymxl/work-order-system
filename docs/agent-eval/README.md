## 1. 两个用例文件（开发 vs 冻结，物理分开）

| 文件 | 条数 | ID | 用途 | 能不能据它调优 |
| --- | --- | --- | --- | --- |
| [`scripts/agent-eval-dev.json`](../../scripts/agent-eval-dev.json) | 12 | `DEV-01`..`DEV-12` | 改 prompt / 规则 / 工具时反复跑 | **能**——它就是干这个的 |
| [`scripts/agent-eval-holdout.json`](../../scripts/agent-eval-holdout.json) | 24 | `01`..`24` | **只**用于最终检验 | **不能**——见下 |

**为什么必须物理分开**（手册 L128）：

> 开发集用于改prompt/规则；冻结集只用于最终检验。若根据冻结失败调优，该集变成开发材料，另建holdout。

所以两份不是"同一文件里的两个数组"：一旦按冻结集的失败去改实现，冻结集就退化成开发材料，
必须**另建一份 holdout** 才能继续叫"冻结"。两文件 ID 不重叠（`DEV-*` vs `01..24`），
校验脚本会同时查"不重叠"。

**本次冻结集是首版**：从未被任何一轮据此调过 prompt / 规则 / 工具 / 契约（本轮只新增文件、未改任何实现）。

## 2. 字段含义（每条用例必备九项）

| 字段 | 含义 | 取值约定 |
| --- | --- | --- |
| `id` | 用例编号 | 冻结集 = 手册 §5.1 矩阵的槽 ID（`01`..`24`）**逐槽对应**；开发集 `DEV-01`..`DEV-12` |
| `question` | 自然语言问题 | 直接喂受理层（`AgentInvestigationService.investigate`） |
| `order_ref` | **结构化起点单引用**（主工单号） | 受理层的**入参**（设计稿 L80：入口固定预读一次主工单并注册 root 引用）；**问题文本只用于分类**，不必（也通常不会）含单号——`question` 与它必须指向同一张单，校验脚本会比对 `fixture.main_order.order_no` |
| `fixture` | 起点单与对照数据约定 | 见 §3；**够 harness 造数即可**，值是约定描述、不是 SQL |
| `expect_problem_type` | 期望问题类型 | `ORDER_STATUS` / `TIMEOUT_SITUATION` / `REASSIGN_HISTORY` / `UNSUPPORTED`；受理期或工具期即拒绝、或故障注入无报告的槽写 `N/A`；无法判定写 `待定` |
| `must_cover_facts` | **必须被证据覆盖**的事实键 | 报告引用的证据里必须出现这些键（§3.1 的完成判据）。**不是引用白名单**——§3.1 只约束"必需事实 + 允许未知 + 禁止项"，从未要求"不得引用其它已登记的已知事实"（2026-10-06 由 `allow_facts` 改名，见下） | 
| `must_declare_unknown` | 必须**显式**标未知的事实键 | 依 D83：空值 ≠ 未知；这里只放"查不到 / 无来源"（如 `order.assignee` 有 id 但 `t_user` 无行、`order.alert_count` 无来源） |
| `forbidden` | 禁止行为 | 跨部门引用 / 原因性结论 / 编造事实 / 引用范围外单号 / 把故障当成功空集 / 把文本当授权。**每条至少一项** |
| `expect_terminal` | 期望终态 | `COMPLETED` / `FAILED(原因码)` / `TIMED_OUT(原因码)` / `CANCELLED(原因码)`；无法判定写 `待定` |
| `basis` | 该期望的出处 | `§5.1 槽NN` 或 `§1 第X题` / 已裁决 D 条目——**不许自造期望值**的溯源 |
| `matrix_expectation`（仅冻结集） | 矩阵"必须检查的结果"列的**逐字照录** | 校验脚本按槽比对，改一个字就报错 |
| `pending`（可选） | 该槽**当前无法判定**的部分 + 缺什么 | 只要出现"待定"就必须非空 |
| `note`（可选） | 补充说明 | 如"该判据是轨迹判据" |

可用的事实键（两个真实工具当前实际返回）：`order.exists` / `order.status` / `order.assignee` / `order.sla_deadline` / `order.accept_events` / `order.alert_count` / `dept.assignee_open_count` / `dept.assignee_open_order_nos`。

> **2026-10-06 两处字段修订**（改的是字段的**语义与结构**，不是期望值）：
> ① 起点单从"问题文本里抠"改成**结构化 `order_ref`**——7 条开发集的问题文本本来就不含单号，
> 旧口径下它们测的是"定位失败"而不是分类质量（见 [`baseline-dev-results.md`](baseline-dev-results.md) 的对照基线）。
> ② `allow_facts` → **`must_cover_facts`**：原语义"引用白名单"取消——它把"多引用了已登记的已知事实"误判成违规，
> 而 §3.1 从未要求过这一点（DEV-01 因此从 ❌ 变合规，属**修口径**不是放宽断言）。

## 4. 评分口径（与手册逐句对应）

| 口径 | 说什么 | 手册出处 |
| --- | --- | --- |
| 判据字段 | 完成判据看 `must_cover_facts`（**必须被覆盖**），禁止项看 `forbidden`；"多引用了已知事实"不算违规 | §3.1（必需事实 + 允许未知 + 禁止项）；见 §2 的字段修订说明 |
| 分母固定 = 计划用例数 | **失败与超时保留在分母**，不缩分母（与 `scripts/triage-eval.py` 同口径） | L145（拟定规模 24×2×3=144）；L202「超时/失败/忙碌仍留分母」；L207（延迟「超时/失败单列并保留」）；L217「所有计划run保留；失败细分，不删除'难例'」 |
| fixed 与 agent **成对**跑 | 同模型 / 同数据快照 / 同权限 / 同任务集 / **同一最高预算**；只策略相关提示不同 | L121–L127；L145 |

| 交错执行 | agent/workflow 先后顺序交错，不把一组都排在网络拥堵时 | L125 |
| 缓存政策一致 | 工具结果缓存两边一致；预读、授权、复核、重试、序列化与**全部物理调用**都计成本 | L127 |
| 温度等参数 | 只用双方都支持的配置；不假定 `temperature=0` 能复现 | L126 |
| 20% 只是**小样本探索阈值** | 措辞**不得**写成"统计显著"或"已测改善" | L219 |
| 记录四类量 | **正确性 / 证据覆盖 / 调用次数 / 延迟**，并**分列失败清单** | L199–L207（事实精确率 / 必需证据覆盖 / 全任务通过率 / 越权 / 成本 / 延迟）；L226–L231（结果表模板 + 「每对样例的差异和失败清单」） |
| 越权与业务写入 | 设计目标 0，但有限测试不证明绝无风险 | L204；L216 |
| 未运行就被拒的样例 | 不计入"模型事实准确率"，但计入边界与整体契约通过率 | L209 |

**本轮不产生任何分数**：C 层未跑，上面的口径是把"将来怎么算"先钉死。

## 5. 判据落在哪一层（报告无自由文本，措辞类怎么判）

`docs/AGENT-PLAN.md` §3.2：报告只提交 `problemType` + 证据编号 + 建议编号，**正文由后端按证据渲染、模型不提交自由文本**。
于是矩阵里"不得说 X"这类检查，落成三条**机器判据**：

1. `must_cover_facts` 覆盖——报告引用的证据必须覆盖这些事实（判据落在证据的 `fact` 上，不落在模型的说法上）；
2. 终态契约——`COMPLETED` 才产出报告，`FAILED/TIMED_OUT/CANCELLED` 报告必须为 `null`；
3. 建议契约——§3.1 的禁止项（`accept_events` 为空 / `assignee` 未分配时不得建议 `CONTACT_ASSIGNEE`）。

措辞类（如"不推断全局负荷"）在渲染层**结构性成立**（渲染器只拼固定文案），
如有争议按手册 §5.2 的人工 rubric 复核——**不用 LLM 裁判当绝对真值**。
判据一律落在**业务 code / 业务状态**上，不落在传输层（`CLAUDE.md` §6 第 6 项）。


## 9. 契约成熟度读数：冻结 24 槽中**可判 24 条**（2026-10-07）

把"冻结集里有多少条现在就能判"单独记一个数——它比"任务集看起来完整"更能说明**契约还差什么**：

| 读数 | 值 | 口径 |
| --- | --- | --- |
| 冻结槽总数 | 24 | §5.1 矩阵（**不改**） |
| **可判** | **24** | `expect_terminal` 与 `expect_problem_type` 都**不是**"待定" |
| 待定 | **0** | —— |

**"可判" 与 "实测结果" 是两件事**（别混）：上面那个 **24** 说的是**契约**（每条期望都有依据、都有判据）；
它**不是**成绩。**实测结果**是另一组数（S6 阶段 2，2026-10-07，真模型单次，见 §13）：

| 实测 | 值 | 口径 |
| --- | --- | --- |
| agent 通过 | **51 / 72** | 24 例 × 3 次（分母固定） |
| fixed 通过 | **30 / 72** | 同上 |
| agent 可靠性收口 | **7 / 72** | `MODEL_TIMEOUT`2 / `RUN_BUDGET_EXCEEDED`1 / `MODEL_PROTOCOL_ERROR`4 |

> ⚠ 这是**单次、小样本**（24 例）→ **不是**统计显著、**不是**泛化证明（手册 L145/L219）。

> ⚠ **24/24 可判，但一条都没跑过**：可判 = "期望有依据、判据可执行"；**不等于**"通过"。
> **"可判"与"可过"的差距**（一句话一条）：
> ① **槽 16 / 17 / 24 有实现**（权限重校验 / 最终复核），但只在**桩**上验证过，真模型下的行为未测；
> ② **槽 21 有实现**（有界重试），同样只有桩证据；
> ③ **槽 23 只落了"名额归还"这一半**——**真正的取消**（interrupt / 连接断开 / 读循环中止 + "取消延迟上界 = 当前轮读超时"）仍属 S4；
> ④ **槽 06 的分页**、**槽 07 的 SLA 规则值**有工具但**没在真模型下走过**；
> ⑤ 全部 24 槽的**终态/质量结论**都要等 **S6 的成对对照**（holdout + agent 侧）——现在**一次都没跑**。

**16 → 18 → 19 → 21 → 22 → 23 的来源**：只有槽 **06 / 07**（工具轮）、**11**（关系轮）、**17 / 24**（最终复核轮）、
**16**（权限重校验轮）与 **21**（有界重试轮）七条，
靠的都是**补期望**（依据 §5.1 矩阵原文 + 设计稿 L85 / L86 / L87 / L92 / **L213**），**不是跑出来的结果**；
配套落地的实现（`read_earlier_events` / `read_sla_context` / 关系第二条 / **最终短读取复核**）
只是把这些期望变成**可满足**，并没有让它们变成"已通过"。**holdout 一次都没运行过**——这一点在数字旁边必须一直写着。

> **槽 17 / 24 为什么能补**：D86 已经把**状态模型**对齐（新增 `INCOMPLETE` 终态、`STATE_CHANGED` 取代 `STALE_EVIDENCE`），
> 本轮补的是**生产者**——最终短读取复核（设计稿 L213）在返回 `COMPLETED` 之前逐字段重查，
> 不一致即 `INCOMPLETE(STATE_CHANGED)`、报告作废、已核实事实保留。两条期望都取
> `INCOMPLETE(STATE_CHANGED)` + `problemType=N/A`（**未完成没有报告**，所以没有 problemType）。
>
> **槽 16 为什么能补**：给 `CANCELLED(PERMISSION_REVOKED)` 造出了**第一个生产者**——每次工具调用前
> 用同一个协作者重校验账号/角色/部门（与受理层同源），撤销即终止、**不切换到新范围**（设计稿 L116）。
> 期望取 `CANCELLED(PERMISSION_REVOKED)` + `problemType=N/A`（已取消同样没有报告）。
>
> **槽 21 为什么能补**：在模型边界实现了**有界重试**（只重试 429/5xx/连接类，次数上限 3、单次等待上限 2s、
> 总等待受运行预算约束、物理调用次数随失败消息回传），矩阵写"**后**可恢复" → 期望取 `COMPLETED`
> （`problemType=N/A`，故障注入槽不判类型）。

**本轮新增的 `INCOMPLETE` 终态与 `STATE_CHANGED` 码不改变这个读数**：它们是为槽 16 / 24 预留的**契约位**，
但生产者（新鲜度校验、运行中状态变化、权限撤销）要等 S4 落地才存在。真正让读数上升的，是"该槽能被判定"，
不是"表里多了一个码"。

**复测要求**：每轮 S4 相关切片落地后**重跑本节读数**并把变化写回这里——
否则会出现"某槽其实已经可判了，但没人知道"，读数字面停留在旧值。

> **对外表述**：引用本节的读数时，口径必须一起带上——可以说 / 不可以说见
> [`docs/AGENT-PLAN.md` §6.1「对外表述边界」](../AGENT-PLAN.md)（包含"agent 更强 / 统计显著 / 生产表现"这几条硬边界，
> 以及"holdout **已跑一次**但只是**单次小样本**、不得下对照结论"这条口径）。

## 10. 怎么跑离线 baseline（harness）

```
mvn -o test "-Dtest=AgentEvalBaselineHarness"
```

| 项 | 规则 |
| --- | --- |
| 类名 | `AgentEvalBaselineHarness`——**故意不带 `Test` 后缀**，默认的 `mvn test` **不会**连带跑它（2026-10-06 实测：依赖起齐后全量 `326 / 0 / 0` 绿，输出里没有它）；它要建库删库，不该污染常规套件 |
| 专用临时库 | `wo_agent_eval_<yyyyMMdd>`，结构克隆自 `work_order_test` + 复制 `t_role` 参考行；**不写** `work_order_test`、**不碰**业务库 |
| 清理 | 跑完按 D19 的**最宽口径**（临时库里**每张表都数一遍**）统计，再 `DROP DATABASE`；计数留在结果文件里 |
| 结果文件 | [`baseline-dev-results-v4.md`](baseline-dev-results-v4.md)（**当前**：关系查询按设计稿收敛之后，dev 数字与 v3 相同：12/12）；v3（关键词调优 + fixture 自检）、v2（起点单结构化）、[`baseline-dev-results.md`](baseline-dev-results.md)（**修复前**对照：测的是定位失败，不是分类质量） |

## 12. 怎么跑 S6 holdout harness（桩 / 真模型）

```
# 桩（阶段 1；零真实费用）
$env:MYSQL_PORT='3307'; $env:MYSQL_PASSWORD='<deploy/.env>'
mvn -o test "-Dtest=AgentEvalHoldoutHarness"

# 真模型（阶段 2；`S6_REAL=1` 时桩端点变成**转发代理**，非注入轮转给真供应商）
$env:S6_REAL='1'; $env:LLM_API_URL='<真供应商>'; $env:LLM_API_KEY='<env 或 %TEMP%>' ; $env:LLM_MODEL='deepseek-flash'
mvn -o test "-Dtest=AgentEvalHoldoutHarness#holdoutPairedStubRun"   # 长跑：务必后台跑 + 写日志（CLAUDE §5）
```

| 项 | 规则 |
| --- | --- |
| 类名 | `AgentEvalHoldoutHarness`——**故意不带 `Test` 后缀**，默认 `mvn test` 不会连跑它 |
| 专用库 | `work_order_holdout`（结构克隆自 `work_order_test` + `t_role`；跑完按 D19 最宽口径统计后 DROP） |
| 模型 | 桩模式 = 本地 HTTP 桩；真模型模式 = **转发代理**（`llm.api.url` 指向代理，代理原样转发请求体给真供应商，并记录物理调用与 usage） |
| 比例 | 24 例 × 2 方案 × 3 次 = **144 次**；失败与超时**保留在分母**；三次结果**全部保留** |
| 结果文件 | 桩：[`s6-holdout-stub-run-20261007.md`](s6-holdout-stub-run-20261007.md)（D97）；真模型：[`s6-holdout-real-20261007.md`](s6-holdout-real-20261007.md)（D98） |
| 冒烟 | `-Dtest=AgentEvalHoldoutHarness#realProxySmoke`（1 例 1 次，先验证代理+真供应商+usage 采集，再跑满 144） |

> ⚠ **桩跑不是成绩**：桩对任何输入返回固定值，只能验证 harness 能跑完、能统计、能**保留失败**。
> **真模型那一遍已跑一次**（2026-10-07），见 §13。
