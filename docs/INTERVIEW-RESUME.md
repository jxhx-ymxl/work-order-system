## 简历"项目经历"段（可直接贴，约 200 字）

**企业工单流转平台** | 后端 Java17/SpringBoot3 · MyBatis-Plus · MySQL8 · Redis · Sa-Token；前端 Vue3+ElementPlus

工单提交→验收全生命周期平台，聚焦**并发正确性与权限控制**：

① **抢单防超卖**：不用分布式锁，靠单条 `UPDATE ... WHERE assignee_id IS NULL AND status='PENDING'` 原子 SQL + 数据库行锁互斥，以受影响行数判定，10 线程并发验证恰好 1 成功；
② **状态机+乐观锁双防线**：合法转移表挡非法跳变，所有更新 SQL 带 `status + version` 条件挡并发重复流转；
③ **驳回防重复提交**：识别"驳回会递增计数、天然不幂等"，用 Redis Lua 一次性 Token + SQL 状态条件双重拦截，普通接口不做无谓防重；
④ **超时释放/SLA 升级兜底**：接单写 Redis 30min 标记，`@Scheduled` 定时扫表兜底（60s 释放超时、5min SLA 升级），升级通知用 Redis `SETNX` 幂等防重复骚扰；
⑤ **RBAC 数据隔离**：权限码 + Sa-Token 注解拦截 + 列表/详情按角色行级过滤（提交人看自己、处理人看自己+待分配池、主管看本部门、超管看全部，升级单仅管理员）；
⑥ **升级单管理闭环**：3 次驳回自动升级，主管/超管可接管（`MANAGE`）或超管强关（`CLOSE`），状态机补全 `ESCALATED_ADMIN` 流转；
⑦ **工单号生成**：Redis 按日自增 `WO-YYYYMMDD-XXXXX`，兼顾日期语义+并发唯一+按日重置；
⑧ **LLM 智能分诊（提效点）**：提交时可让 LLM 自动判类型/优先级，接口化 + 失败降级，不配 key 或调用失败回退默认值不阻塞提交。

**工程习惯**：自审代码发现 SLA 重复通知（每 5 分钟轰炸管理员）、AOP 无上下文回滚、Sa-Token 权限异常 500 等问题并修复；**2C4G 单机 Docker Compose 部署**（6 容器；**容器 RSS 合计 ≈1148 MiB**，取数见 `ASYNC-SCHEDULING-PLAN.md` §1.6.8；容器 swap 已禁用，见 D13）。

## 可展开的技术点（面试弹药）

### 并发正确性
- 抢单为何不用 Redis 分布式锁 → 单行 UPDATE 已由行锁保证互斥，锁用于跨多步临界区；**知道何时不用技术**
- 状态机防跳变 → 代码层合法转移表 + SQL 层状态/版本 CAS

### 容错与兜底
- 超时释放不靠单一触发点 → `@Scheduled` 定时扫表是容错底线，Redis 标记作辅助；消息/回调这类"提速"手段可能丢，扫表不漏
- SLA 通知幂等 → Redis `SETNX sla_notified:{id}` TTL 24h

### 权限
- Sa-Token vs Spring Security → 当前权限模型注解粒度匹配，工程选型看投入产出比
- 数据级行过滤 → 同接口不同角色不同可见行；升级单仅管理员可见（防泄露）

### 防重设计
- 驳回 Token（Redis Lua 原子 GET+DEL）vs 抢单（SQL 天然幂等）→ 识别哪些接口真需要防重
